### AI 활용 전제
이 프로젝트는 **AI 최대 활용**을 전제로 굴린다. Codex는 로컬에서 저장소를 직접 보고 작업하며, `unity` CLI를 통해 Unity 에디터에 실제로 도달한다.

- Codex는 런타임 코드뿐 아니라 **에디터 자동화 도구(`Assets/Editor/`)와 빌드/검증 스크립트**까지 작성한다
- SO 에셋 생성 · 프리팹 조립 · 인스펙터 연결은 손으로 하지 않고 **Codex가 쓴 스크립트를 Codex가 직접 CLI(Pipeline `eval`)로 실행**해 처리한다
- **컴파일 검증도 Codex가 스스로 닫는다** — `unity command recompile` → `console`. "작성했다"가 아니라 "작성했고 컴파일을 확인했다"까지가 한 작업
- 수작업이 3회 이상 반복될 것 같으면 자동화가 빠르다 — 오퍼레이터 3명 × (SO 다수 + 프리팹 + 연결)은 명백히 그 경우다

**사람에게 남는 것**: 아트 생성 · 방향 결정 · 외부 인프라(CORS·패키지 설치) · 되돌리기 어려운 조작 승인. 그 넷뿐이다.

이것은 편의를 위한 선택이 아니라 **심사 기준(Codex Collaboration) 자체에 대한 대응**이다. Codex가 코드만 뱉고 사람이 손으로 조립하는 구조보다, Codex가 파이프라인까지 만들고 검증까지 스스로 돌린 구조가 훨씬 강한 서사가 된다. 그리고 그 과정이 커밋과 `EXPANSION_LOG.md`에 그대로 남는다.

### 반드시 지켜야 할 우선순위 원칙
> **로드아웃 구조 + Addressable을 먼저 세운다. 그 위에 유닛 오퍼레이터를 얹는다.**
> 유닛 쪽이 시간에 쫓겨도 라이브 서비스 어필의 뼈대는 남아야 한다.

단, 이번 스코프에서 **유닛 시스템은 핵심 포함이 확정**되었으므로 병렬로 착수한다. 다만 충돌 시 우선권은 로드아웃/Addressable에 있다.

## 1. 최대 리스크 — 먼저 처리할 것

### R1. Addressable × WebGL 원격 로딩 (치명)
전체 전략이 "라이브 드랍 실동작 시연"에 걸려 있는데, WebGL은 데스크톱과 조건이 다르다.

- **CORS** — 배포 서버에 `Access-Control-Allow-Origin` 헤더 필요. 없으면 로딩 자체가 차단됨
- **압축 형식** — WebGL은 LZMA 불가. LZ4 또는 Uncompressed로 빌드해야 하며 용량이 커짐
- **캐싱** — 파일 시스템이 아닌 IndexedDB. `Caching` API 동작이 다름
- **빌드 시간** — Addressable 도입 후 WebGL 빌드 시간이 크게 늘어남

> **Phase 0에서 다른 작업보다 먼저 스파이크로 검증한다.** 빈 씬 + 더미 스프라이트 1장을 실제 서버에서 WebGL 빌드로 내려받는 것만 확인. 여기서 막히면 전략을 조정할 시간이 있어야 한다.

**폴백 계단** (위에서부터 시도)
1. Addressables 원격 그룹 (목표)
2. `UnityWebRequestAssetBundle`로 AssetBundle 직접 로딩
3. 원격 JSON으로 오퍼레이터 **데이터만** 수신 + 스프라이트는 빌드 내장
   → 3번이라도 "콘텐츠가 데이터로 분리되어 있다"는 논거는 유지된다

### R2. 유닛 시스템이 기존 적 AI를 건드린다
현재 적은 웨이포인트만 따라가고 플레이어 접촉 피해만 준다(GDD가 의도적으로 타겟팅을 배제). 아군 유닛과 교전하려면 **적에게 "전방에 아군이 있으면 정지 후 교전" 상태를 추가**해야 하는데, 이는 기존 검증된 시스템의 수정이다.
→ `EnemyInstance`의 기존 이동 로직을 갈아엎지 말고, **상태 하나를 추가하는 최소 변경**으로 접근할 것.

### R3. 13일 일정에 버퍼가 거의 없다
아래 일정은 4트랙 병렬을 전제로 겨우 맞는다. 지연이 발생하면 **§6 폴백 순서**에 따라 잘라낸다.

## 2. 확정된 설계 결정

아래는 확정. Codex는 이 결정을 전제로 작업한다.

### 2-1. 오퍼레이터 구성 — 3명
| # | 오퍼레이터 | 유형 | 배치 |
|---|---|---|---|
| 1 | 카시아 (기존) | 타워 중심 | 빌드 내장 |
| 2 | 신규 | **유닛 지휘형** | 빌드 내장 |
| 3 | 신규 | 자유 | **원격 전용 — 빌드에 미포함** |

3번이 빌드에 없어야 라이브 드랍 시연이 진짜가 된다. 이것이 시연의 핵심.

### 2-2. 유닛 자원 — 골드와 분리된 별도 자원
"지휘 포인트"(가칭). 시간에 따라 자동 회복.

**근거**: 골드를 공유하면 타워와 유닛 선택이 단순 비용 비교로 환원되고, 소모성(유닛)과 영구성(타워)의 밸런싱이 어려워진다. 별도 자원 + 자동 회복이면 소환 리듬이 생기고, **오퍼레이터마다 자원 체계가 다른 것 자체가 로드아웃 차별화의 실증**이 된다. 구현 비용도 낮다(필드 + 회복 타이머 + HUD).

### 2-3. Addressable 로딩 시점 — 오퍼레이터 선택 화면에서 개별 로딩
타이틀에서 일괄 로딩하면 대기 시간만 길고 "라이브로 받아오는" 것이 눈에 보이지 않는다. 선택 화면에서 미보유 오퍼레이터를 누르면 **다운로드 진행률이 보이고 → 완료 후 플레이 가능**해지는 흐름이 시연에서 훨씬 강력하다.

### 2-4. 아군 유닛도 "순수 C# 인스턴스 + View" 패턴
`AllyUnitInstance`(순수 C#) + `AllyUnitView`(MonoBehaviour). 프리팹은 **1개**, 종류 차이는 `AllyUnitDefinition` 주입.
적(`EnemyInstance`/`EnemyView`)의 구조를 그대로 미러링한다.

### 2-5. 유닛 소환/순회 주체 — `UnitDeployController` (새 매니저 아님)
매니저 원칙(게임 흐름 단계당 1개)을 지키기 위해 `AllyUnitManager`를 만들지 않는다.
대신 `TowerBuildController`와 **대칭되는 컨트롤러**를 두고, 이 컨트롤러가 소환 입력 처리 + 자기가 소환한 `List<AllyUnitInstance>` 순회(`Tick`)를 담당한다.
(타워는 MonoBehaviour라 스스로 `Update`하지만, 유닛은 순수 C#이라 누군가 순회해야 한다. 적은 `WaveManager`가 그 역할을 하고 있다.)

### 2-6. 유닛 효과도 SO 훅 패턴
`IAllyUnitEffect` / `AllyUnitEffectBase`(SO). 기존 `ITowerEffect` 패턴 그대로.
**이유**: 신규 오퍼레이터가 새 유닛을 가져올 때마다 새 C# 클래스가 필요하면 "코드 수정 없는 데이터 드랍" 주장이 무너진다. 초기 효과 세트를 충분히 범용으로 만들어(근접 공격 / 원거리 공격 / 아군 힐 / 주변 버프) 이후 유닛은 조립만으로 나오게 할 것.

### 2-7. 해금 조건 — 누적 최고 도달 웨이브
`PlayerProfile.bestWave`가 임계치를 넘으면 오퍼레이터 해금. **임계치는 낮게 잡는다**(심사위원이 오래 플레이하지 않는다). 디버그로 즉시 해금하는 경로도 남길 것.

## 6. 폴백 순서 (일정 지연 시 잘라낼 순서)

위에서부터 먼저 잘라낸다.

1. **3번 오퍼레이터의 게임플레이 완성도** — 라이브 드랍 시연용이므로 최소 구성만 갖추면 됨
2. **유닛 효과 4종 중 힐/버프** — 근접/원거리만으로도 유닛 전투는 성립
3. **오퍼레이터 3명 → 2명** (단, 원격 전용 1명은 반드시 남긴다 — 시연의 근거)
4. **Addressable → 폴백 계단 하향** (§1 R1)
5. **유닛 시스템 전체** — 최후의 수단. 이 경우 로드아웃 차별화는 타워 풀 조합 + 플레이어 스탯 보정으로만 표현

**절대 자르지 않는 것**: 오퍼레이터 로드아웃 구조 / 원격 로딩 실동작(어떤 폴백 단계로든) / PlayerProfile 분리.
이 셋이 Release Potential 논거의 전부다.

## 7. 제출 시 명시할 신규 개발 범위

대회 요건상 기존 프로젝트 활용 시 **챌린지 기간 신규 개발분을 명시**해야 한다. `nexon-final` 태그 이후 커밋 전체가 이에 해당하며, 문서로는 아래를 기재한다.

- 오퍼레이터 로드아웃 시스템 (`OperatorDefinition` 및 적용 파이프라인)
- 오퍼레이터 선택 UI
- 아군 유닛 시스템 (데이터·인스턴스·뷰·효과 훅·소환 컨트롤러·지휘 포인트 자원)
- 적 교전 상태 추가
- `PlayerProfile` 영속 데이터 분리 및 저장소 인터페이스 추상화
- 오퍼레이터 해금 시스템
- Addressable 기반 오퍼레이터 패키징 및 원격 로딩
- 신규 오퍼레이터 2명 및 유닛 아트 에셋 일체
